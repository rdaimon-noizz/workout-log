# 筋トレ記録（workout-log）

ジムでスマートフォンから数秒で筋トレを記録し、前回記録・履歴・種目別の重量推移を確認でき、全データを CSV で持ち出せる個人用 Web アプリ（PWA）です。

- **ローカルファースト**: サーバーを持ちません。データはすべて端末ブラウザの IndexedDB に保存され、外部へ送信されません。
- **オフライン動作**: Service Worker がアプリ本体を事前キャッシュするため、電波の無い場所でも起動・記録できます。
- **持ち出し**: 「データ」タブから CSV（分析用）と JSON（バックアップ／復元用）で全データを書き出せます。iPhone では共有シートが開き、「ファイルに保存」や AirDrop で渡せます。

## 技術スタック

TypeScript / Vite / React / React Router / Dexie（IndexedDB）/ Tailwind CSS / vite-plugin-pwa / Recharts（グラフ。種目別履歴の画面だけ別チャンクで遅延読み込み）/ Vitest / ESLint

## セットアップ

Node.js 22 以上が必要です。

```bash
npm install
npm run dev        # 開発サーバー（http://localhost:5173）
```

## デプロイ（GitHub Pages）

`main` ブランチへ push すると GitHub Actions（`.github/workflows/deploy.yml`）が lint / typecheck / test / build を実行し、GitHub Pages へ配信します。

- 配信 URL は `https://rdaimon-noizz.github.io/workout-log/`
- サブパス配信のため、CI では環境変数 `VITE_BASE=/workout-log/` を渡してビルドしています。ローカルで同じビルドを再現する場合は PowerShell で `$env:VITE_BASE='/workout-log/'; npm run build` を実行してください（Git Bash では `/workout-log/` が Windows パスに変換されてしまうため、`MSYS_NO_PATHCONV=1` を付けるか PowerShell を使います）。
- GitHub Pages に SPA 用のフォールバックは無いため、ビルド後に `index.html` を `404.html` としてもコピーしています。

## iPhone へのインストール

1. Safari で配信 URL を開く
2. 共有ボタン →「ホーム画面に追加」
3. 以後はホーム画面のアイコンから起動する

ホーム画面に追加したアプリと Safari は保存領域が別です。**先にホーム画面へ追加してから記録を始めてください**（Safari 上で入力したデータはホーム画面版には引き継がれません）。
データは端末内にのみ保存されるため、アプリの削除や「Safari の履歴と Web サイトデータを消去」で消えます。定期的に JSON バックアップを取ってください。

## 使い方（記録）

1. ホームの「新しいトレーニング」で日付・開始時刻（初期値は現在時刻。「今の時刻にする」で戻せる）・体重（任意）・メモ（任意）を入れて開始する。進行中のトレーニングがあれば自動で終了する。開始・終了時刻は後から「編集」で直せる。
2. 「＋ 種目を追加」で種目を検索して選ぶ。無ければその場で作成できる。
3. セット入力画面で重量・Reps・秒（と任意のメモ）を入れて「セット追加」。Reps と秒はどちらか一方でよい（プランクは重量 0・秒 60、ポーズデッドリフトは重量 200・Reps 3・秒 2 など）。追加後も重量・Reps・秒は残るので、同じ重量なら次のセットは 1 タップ（メモだけ空に戻る）。追加直後はボタンが「✓ n セット目を追加」に変わって約 1.5 秒無効になり、二重タップで同じセットが 2 本入らない（振動は Android のみ。iOS は Web から振動を出せない）。
   - **Reps 0 = リフト失敗**（1 回も挙げられなかった）。`230 kg × 0（失敗）` と表示され、最高負荷・推定 1RM には数えない（ボリューム 0、セット数には数える）。途中で潰れたときは挙がった回数を入れ、必要ならメモに書く。
4. セット行をタップすると編集・削除。ヘッダーの「削除」で種目ごと削除。
   トレーニング詳細の種目一覧で「並べ替え」を押すと ▲▼ で種目の順番を入れ替えられる（記録をあとから入れたときの並び直し用。終了済みでも可）。
5. 「トレーニングを終了」で終了時刻を記録する。終了後もセットの編集はできる。

## 使い方（週ごとの集計・部位別）

- 「履歴」の「週ごとの集計」で、直近 12／26／52 週の推移を棒グラフと表で見る。対象は全種目・種目・部位から選び、指標はボリューム（Σ 負荷×回数）・セット数・回数・合計時間・トレーニング日数。記録の無い週は 0。
- 「部位別（週）」で、1 週間のセット数とボリュームを部位ごとに横棒で並べる。‹ › で週を移動。行をタップするとその部位の週ごとの推移へ。
- 週は月曜始まり。複数の部位を持つ種目は、それぞれの部位に満額で数える（分割しない）。部位の無い種目は「部位未設定」。週の合計は部位の重複を数えない実数。

## 使い方（自重種目）

- 懸垂・ディップス・腕立てなどは、種目フォームの「自重種目」スイッチを入れる。一覧に「自重」の印が付く。
- 自重種目のセット入力では重量欄が「加重」になる。何も付けなければ 0、ディップスに 10 kg 付けたら 10。負荷はアプリが「体重 + 加重」で計算し、入力欄の上に「体重 72.5 kg ＋ 加重 10 kg ＝ 82.5 kg」と出る。
- 体重はそのトレーニングに入力した値を使う。入力していない日は、直近で体重を入れた日の値を使い「（9/10 の記録）」と出典を示す。どこにも無ければ「負荷 不明」になるので、トレーニングの「編集」で体重を入れる。
- 表示は「自重+10 kg × 8」と負荷「82.5 kg」。種目別のグラフは自重種目では負荷（体重 + 加重）の推移になり、体重が分からない日は点を打たない。

## 使い方（履歴）

- 「履歴」タブにトレーニングが新しい順に並ぶ。タップするとその日の全種目・全セットを見られ、そこからセットの編集もできる。
- 「種目別の履歴・重量推移」で種目を選ぶと、Workout ごとの推移グラフと日付ごとのセット一覧が出る。グラフの上のボタンで指標を切り替えられる（点をタップすると日付と内訳）。

| 指標 | 計算 | 対象セット |
|---|---|---|
| 最高負荷 | 負荷の最大 | 負荷が分かる全セット |
| ボリューム | Σ 負荷 × 回数 | 回数のあるセット |
| 負荷×時間 | Σ 負荷 × 秒 | 秒のあるセット |
| 合計時間 | Σ 秒 | 秒のあるセット |
| 推定1RM | 最大の 負荷 × (1 + 回数 / 30)（Epley 式） | 回数のあるセット |

  負荷は通常種目では重量、自重種目では体重 + 加重。その種目の記録に値が無い指標のボタンは出ない（プランクにはボリュームが出ない等）。指標は保存せず、表示のたびに計算する。
- セット入力画面の上部に「前回」として、同じ種目を前にやった日の全セットが出る。セットがまだ無いときは前回の 1 セット目が入力欄の初期値になる。

「種目」タブで種目をタップすると、既存の種目（初期7種目を含む）の名前・部位・「自重種目」の印を変更できる。作成・アーカイブ（選択肢から外す。過去の記録は残る）・復元もここで行う。セット入力画面のヘッダー「種目編集」からも同じ編集ができる。部位は候補（大胸筋・広背筋・僧帽筋・脊柱起立筋・三角筋・上腕二頭筋・上腕三頭筋・前腕・腹直筋・腹斜筋・大腿四頭筋・ハムストリング・大臀筋・内転筋・ふくらはぎ・全身・その他）から複数選べ、無い部位は自由に追加できる。追加した部位は次回から候補に出る。

## 使い方（データ）

- 「データ」タブの「CSV を書き出す」で全セットを CSV に、「JSON バックアップを書き出す」で全データを JSON に書き出す。iPhone では共有シートが開くので「ファイルに保存」「AirDrop」などを選ぶ。PC ではダウンロードになる。
- 「JSON バックアップから復元…」でファイルを選ぶと、件数を確認したうえで現在のデータをすべて置き換える。復元は 1 つのトランザクションで行い、途中で失敗した場合は元のデータのまま。版 2 のバックアップも復元できる（自重種目の印は「なし」で補う）。
- 同じ画面に件数・保存領域の永続化状態・アプリの版が出る。

## データの規約

- 重量は kg。小数可（2.5 kg・1.25 kg 刻みなど）。
- 自重種目（`usesBodyweight`）では `weightKg` は加重（付けた重さ。無ければ 0）。負荷 = 体重 + 加重 で、体重はそのトレーニングの値 → 無ければ直近で体重を入れた日の値 → 無ければ不明。負荷は保存せず表示・グラフ・CSV のたびに計算する。
- 秒はセットごとの任意項目。ホールド時間（プランク）として使うか、ポーズ秒（ポーズデッドリフト）として使うかは**同じ種目の中では統一**する。
- 部位は文字列の配列。表記ゆれ（「広背筋」と「背中」など）は分析時に別物になるので、候補にあるものは候補から選ぶ。
- ダンベル種目を片手の重量で記録するか合計で記録するかは決めていません。**同じ種目の中では統一**してください（分析時に混ざると比較できなくなります）。
- 日付（`date`）は端末ローカルの `YYYY-MM-DD`。時刻は ISO 8601 オフセット付き（例 `2026-09-18T19:30:00+09:00`）。
- ID は UUID。

### データモデル

| テーブル | 内容 | 主な項目 |
|---|---|---|
| exercises | 種目マスタ | name, nameKey（一意）, muscles（部位の配列）, usesBodyweight（自重種目か）, archivedAt |
| workouts | 1 回のトレーニング | date, startedAt, endedAt, bodyweightKg, memo |
| exerciseSessions | Workout 内の 1 種目 | workoutId, exerciseId, order, memo |
| workoutSets | 1 セット | exerciseSessionId, setNumber, weightKg, reps（null 可）, durationSec（null 可）, memo |

種目の削除は物理削除ではなくアーカイブ（`archivedAt`）です。過去の記録は残ります。
スキーマの版は 3 です。版 1（部位が単一の category、秒なし）・版 2（自重種目の印なし）で保存されたデータは、初回起動時に自動で変換されます。

### CSV

1 行 = 1 セット。UTF-8 with BOM、CRLF。列順は次のとおり固定し、将来の追加は末尾にのみ行います。

```
date, workout_id, started_at, ended_at, bodyweight_kg, workout_memo,
exercise_id, exercise, exercise_muscles, exercise_order, exercise_session_id, exercise_memo,
set_id, set_number, weight_kg, reps, set_memo, set_created_at, duration_sec,
is_bodyweight_exercise, load_kg
```

- `weight_kg` は自重種目では加重。`is_bodyweight_exercise` は 1/0。`load_kg` は負荷（自重種目は体重 + 加重、体重が分からなければ空。通常種目は重量）。`bodyweight_kg` はそのトレーニングに入力した値そのもの。

- pandas で読む場合は `pd.read_csv(path, encoding="utf-8-sig")` を使ってください（既定の `utf-8` だと先頭列名に BOM が混じります）。
- `exercise_muscles` は部位を `;` 区切りで 1 列に入れます（pandas では `str.split(';')` → `explode` で部位別に集計）。`reps` と `duration_sec` は無い側が空になります。`reps` の 0 はリフト失敗（挙がらなかったセット）です。
- セットが 1 つも無い Workout は CSV に現れません。
